Building Web Scrapers for Greek News Outlets

Navigating HTML structures and dynamic content

The Initial Approach

Initially we try to build a scraper that works universally[cite: 1]. The first problem we encounter is how to actually find the articles[cite: 1]. To do this, we need to fetch the HTML of the webpage and parse it[cite: 1]. Parsing involves creating a parse tree that makes the document navigable, and for this task we use BeautifulSoup[cite: 1]. This Python library transforms the raw, messy HTML into a structured tree of objects, allowing us to easily search for specific tags and classes to extract our data.

Filtering the Noise

Once we can navigate the HTML, the next problem is how to separate the article titles and links from other things such as ads[cite: 1]. Also, we need to figure out how to exclude articles of minor importance[cite: 1]. These minor articles usually arise because modern news websites heavily utilize sidebars, "trending" carousels, and sponsored widgets to keep users engaged, which clutters the main news feed we are actually interested in[cite: 1].

The solution to this filtering problem is using regex (regular expressions)[cite: 1]. By compiling a regex pattern, we can search for partial string matches within class names, allowing us to target relevant article containers while bypassing standard ad blocks and minor story cards. Moving to Per-Source Scrapers

Despite the regex approach, the universal scraper ultimately failed. The problem lies in the differences in where the article title is "hidden" in the HTML structure across different sites[cite: 1]. Some sites nest the title in an h2 tag within a specific div, while others use custom article tags or bury the link inside a series of span elements. It becomes impossible to use the same scraper everywhere[cite: 1].

The solution was providing the fetched HTML to Gemini Pro and creating per-source scrapers[cite: 1]. This involved iterative improvements of each one of the scrapers, checking edge cases, and refining the logic, which proved to be very time consuming[cite: 1]. Main Ideas

Looking at the final custom scrapers, a common methodology emerges[cite: 1]. Instead of trying to pinpoint the exact target immediately, we use a two-phase approach. Phase 1 involves aggressive pruning with regex, where we actively search for and decompose unwanted sections (like sidebars, carousels, and widgets). Phase 2 focuses on extraction, where we look at the remaining, cleaned HTML and anchor directly to the heading tags to extract the headlines and URLs safely.
