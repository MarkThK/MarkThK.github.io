Building Web Scrapers for Greek News Outlets

Navigating HTML structures and dynamic content

Introduction to the Task

To continue the project, we will need to retrieve the article titles from the websites. To this end, we continue by building scrapers that work for the current layouts of the websites we are interested in. This proved to be quite a tedious task: On the one hand, the complexity of a website's structure made the search for the titles quite complicated. Various tools (from parse trees, to regular expressions and to LLMs). On the other hand the large differences in the structure of the different websites meant that a different scraper had to be created for every website.

This post showcases how these challenges were overcome and concludes with two examples of the scrapers produced.

The Initial Approach

Our first attempt is for a scraper that works for all websites. The main problem that we encounter, after fetching the HTML code, is how we can automatically find the article titles and links. We thus look for patterns in the HTML structure that indicate where these elements are located. Across the news websites considered in this work, article titles are typically embedded within hyperlink (<a>) tags, often enclosed by heading elements such as <h2> or <h3>, or placed inside article containers identified by characteristic classes or attributes. Although the exact HTML structure differs from one website to another, these recurring structural features provide useful cues for locating news articles while excluding navigation menus, advertisements, and other unrelated content.

To analyze the HTML and identify such patterns, we first parse the document into a tree structure that captures the hierarchy of nested tags. Then, to navigate to the article titles, we use Beautiful Soup, a Python library that allows us to search for specific tags and attributes and extract the information they contain. This enables us to automate the search for the important elements in the HTML code.

Filtering the Noise

However, not every header with hyperlink is a relevant news title. Ads can also contain text with hyperlinks, for example. Moreover, there are articles of minor importance (such as articles that only appear as related to a main one), which are better to exclude for capturing the edeitorial choices of the outlet. Other examples of such minor articles arise from sidebars, such as "trending" carousels (or "ροή ειδήσεων" sections in greek websites).

Given the different names given to their respective HTML classes (class names can contain keywords such as 'ad', 'widget', or 'carousel'), regular expressions are a natural solution. The regex package in python allows us to compile an abstract string (for example, an abstract representation for all the strings that contain the keyword "ad" in them). Thus we can exclude filter more easily for ads and minor articles, without hardcoding the exact class names to be excluded.

Since the HTML structure is quite complicated, the task of finding the patterns that indicate the presence of an article title was handed over to an LLM. Gemini Pro was essential for constructing all the following scrapers, as with a few rounds of feedback about omitted items, it was able to successfully construct them. However, before constructing any scrapers, it needed access to the HTML source code of the websites. This could only be provided manually. Therefore, the next step was to create a small script that retrieves and saves the HTML.

Fetching the HTML

Moving to Per-Source Scrapers

Despite the regex approach, the universal scraper ultimately failed. The problem lies in the differences in where the article title is "hidden" in the HTML structure across different sites. Some sites nest the title in an h2 tag within a specific div, while others use custom article tags or bury the link inside a series of span elements. It becomes impossible to use the same scraper everywhere.

The solution was working with the LLM to create per-source scrapers. This was a particularly time-cocsuming task, since it required various rounds of improvement. Here are two examples of the resulting custom scrapers:

The approach often used to construct the scrapers is the following: a first phase of processing performs aggressive pruning with regex, where we search for and decompose unwanted sections (like sidebars, carousels, and widgets). After only the more relevant contents remain, the scraper looks at the remaining HTML and anchors directly to the appropriate (for the given source) heading tags, to extract the headlines and URLs safely.

Conclusion and Moving Forward

We now have scrapers that work for the current versions of our sources' websites. With minor adjustments, they will be able to retrieve the most recent news titles from the wayback machine. Furthermore, the gained experience will allow us to successfully create scrapers for the older layouts of the websites.

The project now turns to acquiring the websites from the internet archive. Before starting to download, we must determine which snapshot we will use. In the next post, the Wayback Machine API will be used to inquire about available snapshots and an algorithmic approach will be developed to ensure that days with snapshots from all the sources are prioritised.

Some sources, which have rarer snapshots and would harm the reliability of our results, will be abandoned.
